TASK
You fill an ELN (electronic lab notebook) for one raw scanning probe microscopy (SPM) data file.
Technique: AFM (atomic force microscopy). Application definition: NXafm.
The pynxtools-spm converter reads the ELN to write a NeXus file.

FILES (given to you as context; Galaxy adds a number in front, e.g. "3_readme.txt")
- eln_instructions.txt: this file. NOT A SOURCE. Never quote it and never take values from it.
  Its examples are about other materials and only show the format.
- base_eln.txt: the ELN to fill, in YAML. NOT A SOURCE. Its values come from the Zenodo record
  and the raw file header.
- <raw file>_header.txt, if given: the text header of the raw file. A source.
- All other files: the dataset's context files (readme, notes, text of the paper and its
  supplement). Sources. The text of a PDF is given as a .txt file with the PDF's name.

RULES
1. Use only facts written in the source files. Never guess or use outside knowledge.
2. Fill only the fields of base_eln.txt whose value is null. Keep every other value as it is.
   Do not add, remove or rename keys.
3. If a value is not in the source files, leave it null. Do not write "unknown".
4. Every value you fill needs evidence: a quote of at most 25 words and the file name.
   - Copy the quote character by character from the file. Do not reword, shorten inside,
     join pieces or fix spelling; write line breaks as spaces.
   - The quote must contain the fact itself (for example the material or the value).
   - Give the file name exactly as you received it, without wildcards.
   - If you cannot find such a quote, leave the field null.
5. Prefer facts about THIS raw file (identifier_experiment in base_eln.txt). Use the readme and
   the header to find which figure and which measurement it belongs to, then use only that part
   of the paper. Do not add facts from other figures or other raw files.
6. scan_mode: exactly one of these values, as written here:
   contact mode, tapping mode, non-contact mode, peak force tapping mode
7. Sample.Sample_component.chemical_formula: the formula as the source writes it, without spaces.
   - Element symbols with their counts; a count of 1 is left out. Groups in parentheses or
     brackets with a count, and a hydrate dot, are allowed. Do not reorder the elements.
   - No phase, surface or structure marks; put those in the description.
   - If the sample has no single formula (a mixture, a protein), leave it null.
   Form: <element><count><element><count>...
   Example: "MoS2"
8. Sample.name and Sample.Sample_component.name: the material as the files write it (formula,
   phase, surface), plus English words for its form (single crystal, thin film, flake, powder).
   - ASCII only: spell Greek letters (alpha-, beta-), no subscripts, no markup.
   - Do not invent a long English chemical name; it may go in the description.
   Form: <phase>-<formula>(<surface>) <form>
   Example: "2H-MoS2(0001) flake"
9. experiment_description: 1 to 3 sentences: what was measured in this raw file and why.
10. Write in plain English, short and factual.

FIELDS YOU MAY FILL (only where base_eln.txt has null)
- Instrument.hardware.model: the AFM instrument model, if named
- Instrument.hardware.model/@version: the instrument version, if named
- Instrument.software.model: the control software, if named
- Sample.History.Note.description: how the sample was grown and prepared (cleaving,
  deposition, annealing, ...)
- Sample.Sample_component.chemical_formula: see rule 7
- Sample.Sample_component.description: the material, its phase and surface, and what is on it
  for this raw file
- Sample.Sample_component.name: see rule 8
- Sample.name: see rule 8
- experiment_description: see rule 9
- scan_mode: see rule 6

OUTPUT FORMAT
Answer with exactly two fenced YAML blocks and nothing else.

Block 1, the filled ELN: all of base_eln.txt, with the same keys in the same order.
```yaml
<the ELN>
```

Block 2, the evidence: one entry per field you filled, named as under FIELDS YOU MAY FILL.
```yaml
evidence:
  <field name>:
    file: <file name as you received it>
    quote: "<quote copied character by character>"
```
